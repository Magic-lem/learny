# Learny Demo 实施计划

Demo 交付一个可安装的 dsh 插件，让用户在真实材料上完成学习、笔记积累与整理、实践验收、复习、跨聊天继续、成果生成和面试补课。产品行为见 [产品设计](product-design.md)，开发版本见 [dsh 开发基线](runtime-baseline.md)。

当前已实现 M0 基础和 M1 固定学习闭环、AI 笔记整理；M1 已完成自动化检查与 Web Host 真实模型验收，见 [M1 实现记录](m1-implementation.md)。M0 的 Web 界面和 Desktop Host 安装验证见 [M0 实现记录](m0-implementation.md)。Desktop 原生窗口待验收，M2–M3 尚未实施。

## 1 演示场景

首选场景为“学习 dsh 的一次工具调用链路”。材料以已固定的源码版本为准，选择一条有限执行路径，并补充少量官方原理资料。实际源码入口和验收题在 M1 准备时核对，不从旧版本文件名推定。

建议设置 3 个节点：工具如何注册并被模型看到；一次调用如何执行并返回结果；调用结果如何支持后续推理及日志追踪。实践可包含追踪一个现有工具、解释一次真实调用，随后完成一个最小插件工具实验。每个节点明确任务要求和可观测的验收结果。

该场景是示例内容，不限制 Learny 的产品范围。独立主题空间保留创建与路线入口。

## 2 M0 插件集成

### 交付内容

- 一个独立的 `dsh-plugin-learny` 包，含 Host、Client 入口和 bundle/profile 配置。
- 一个能在右侧打开的 React 面板。
- 创建与读取学习空间的最小自定义接口。
- 一个经过 schema 校验并使用本地后端的持久记录。
- 最小 Markdown 文件创建与读取验证，确认笔记正文保存位置和文件权限。
- 打包产物、独立测试 profile 和可复现的安装说明。
- Web 开发环境验证，以及 Desktop 中的插件加载和数据往返验证。

### 必须先解决的问题

确认第三方包的 Host 接口如何生成 Typert 元数据，生成的 Remote 如何在 Client 装配，以及 Host 与 Client 依赖如何与宿主共享。验证 package exports、Client bundle、静态资源和卸载生命周期。

优先使用已发布扩展点；如存在无法通过外部插件完成的装配限制，记录具体失败、可行替代方案及需要的宿主改动，重新确定实现方式。不能把源码目录中手工接线的成功当成独立插件安装成功。

### 验收

在独立测试 profile 安装打包产物，打开面板，创建空间并写入一份 Markdown 文件，刷新并读取，再退出宿主并重启读取。记录安装版本、数据库与文件位置、运行平台、命令和验证结果。安装、刷新、重启任何一条失败，M0 不算完成。

## 3 M1 固定内容的学习闭环

### 交付内容

- 人工准备的 3 节点示例地图、有限材料清单和验收规则。
- 当前任务的预测、阅读、实践、解释和评价阶段。
- 用户提交、辅助记录、评价、补课任务和历史查看。
- 基本笔记列表、编辑、预览、查找和本地 Markdown 保存，当前任务内可随手记录。
- 按用户指令补充、润色和排版，保存原文快照、来源与整理版本，支持对比和撤销。
- 学习空间与聊天绑定，换聊天和重启恢复。
- 基于实际提交的模型评价；路线暂时使用示例数据。

### 验收

完整执行一个节点：先预测，按入口阅读，提供实践证据并解释，保存评价。请求提示后不能直接成为独立通过；未满足标准能进入补课。随后新建聊天关联该空间，继续同一任务，重启后记录一致。

阅读过程中记录自己的想法，将零散笔记按用户要求整理，分别验证补充、润色和只调整排版。笔记在换聊天、重启及外部编辑后仍能读取；过期整理不能覆盖新内容。笔记修改不影响已提交的实践解释。

验证模型失败时提交仍被保存，评价可单独重试；同一提交的重复请求不会产生重复的有效记录。

## 4 M2 个性化路线与 Agent 工具

### 交付内容

- 目标、基础和时间采集，少量诊断题。
- 读取选定材料，登记来源及版本，按需补充外部原理资料。
- 模型生成地图、程序校验依赖和来源、用户确认路线。
- Agent 工具读写受控业务动作，使用同一领域服务。
- 调整目标、版本化路线、复习建议和资料变化提示。
- 笔记与节点、材料的关联，笔记疑问转为补课任务，基于笔记的回忆问题和复习记录。

工具接口至少覆盖读取空间、获取当前任务、提交路线提案、提交评价提案、提出补课任务，以及读取和按用户意图整理指定笔记。笔记写入复用领域服务，校验输入版本并保留原文；自动保存由界面触发。用户实践提交由界面保存，工具不提供任意写入能力状态的操作。

### 验收

创建一个新目标，生成包含材料、任务和标准的路线。非法依赖和无效来源被拒绝；用户调整目标后生成新版本，旧任务和实践证据可追溯。进入新聊天时，通过日志可追踪的上下文读取当前进度。

从一篇关联笔记发起复习，先回答自测问题，再展开正文核对；记录回忆结果和新的理解，将一个笔记疑问加入补课任务。

## 5 M3 成果面试与安装交付

### 交付内容

- 项目总结、贡献和指标补充表单、简历草稿版本与文本导出。
- 选用指定笔记版本生成成果，笔记 Markdown 导出与来源保留。
- 围绕成果和能力节点的面试问答与评价。
- 面试缺口加入学习路线。
- 五个工作台视图的整合、失败与中断反馈。
- 在干净测试环境中的安装说明、示例材料和演示记录。

### 验收

执行产品设计中的 A01 至 A14。项目总结能追溯来源与所引用的笔记版本，缺少个人贡献或指标时形成待补信息。面试产生至少一个可继续执行的补课任务。笔记和成果导出能够再次读取，运行中断后不自动重复实践命令。

## 6 拟议代码组织

保持一个插件包，内部按职责组织；具体构建配置在 M0 按宿主版本确认。

| 目录 | 职责 |
| --- | --- |
| `src/core` | 类型、教学状态机、笔记修订、评价与成果规则 |
| `src/host` | 领域服务、Remote API、Agent 工具、笔记整理和材料访问 |
| `src/client` | 工作台视图、Markdown 编辑与预览、接口调用、提交与状态展示 |
| `src/storage` | 领域 schema、笔记文件与版本、持久化和恢复 |
| `fixtures` | 示例材料清单、学习地图、题目与验收规则 |
| `tests` | 核心规则、接口、安装和恢复验证 |

UI API 与 Agent 工具复用领域服务。运行时依赖固定为兼容的精确版本，避免对所有宿主版本作未经验证的兼容声明。

## 7 验证策略

核心规则验证非法依赖、证据不足、辅助程度、重复提交和成果信息缺失。Host 与 Client 验证数据往返、错误显示和重连快照；持久化验证真实重启恢复。教学过程使用固定材料和可复现记录，并补充真实模型验收。

笔记验证原文恢复、整理范围与来源、保存失败、外部修改冲突和重启恢复；通过有意义的文本变化验证润色与排版。复习和成果引用固定笔记版本，防止后续编辑改写历史记录。

产品输出保存示例或回放记录，检查用户看到的提示、评价和成果内容。安装测试使用打包产物，Web 成功与 Desktop 成功分别记录。

构建和自动化检查随对应里程碑实施，实际结果记录在实施文档中，不能将规划中的验收项视为已通过。

## 8 完整演示脚本

1. 在基线宿主中安装 Learny，打开工作台。
2. 创建示例学习空间，填写目标和基础，查看 3 节点路线。
3. 进入节点，保存预测，打开源码和原理资料，记录自己的想法和疑问。
4. 指定一篇笔记进行补充、润色或排版，对比整理版本，恢复一次原文。
5. 请求一次提示，提交实践结果和自己的解释，查看辅助完成与补课理由。
6. 再次独立提交，查看逐条验收依据。
7. 新建聊天关联同一空间，确认当前进度和笔记；退出并重启，再次确认。
8. 从关联笔记完成一次回忆练习，核对正文并记录新的理解。
9. 选用笔记和实践记录生成项目总结，补充真实贡献；保留一个缺失指标并查看待补项。
10. 导出笔记与简历草稿，完成面试追问，将薄弱点加入路线。

演示内容与真实结果分别保存，个人贡献使用用户提供的实际信息或明确标注的虚构演示数据。
