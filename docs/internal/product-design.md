# Learny 产品设计

Learny 将项目材料、技术原理、个性化路线、分阶段任务、个人笔记和实践评价组织成一个持续的学习过程。学习者每次进入都能知道下一步做什么，在学习中记录和整理自己的理解，并逐步积累能够独立解释、实际完成和用于表达的能力证据。

本设计面向基于 DeepSeek Harness 的单用户 Demo，覆盖学习、笔记、复习、验收、项目总结、简历草稿和项目面试。所有功能均为拟实现需求，当前实现状态与阶段交付见 [Demo 实施计划](demo-plan.md)。

版本：0.2。更新日期：2026 年 10 月 8 日。产品名：Learny，暂定。

## 1 产品目标与用户

### 要解决的问题

学习者面对一个项目时，往往不知道从哪里开始、哪些内容值得学、基础知识与源码如何对应。普通问答可以快速给出总结，但学习者容易把读懂答案当成自己已经掌握，过一段时间仍难以复述或动手完成。

Learny 将每个学习目标落实为有限任务。先让用户表达自己的判断，再提供阅读线索和必要提示，通过实践与自己的解释确认掌握程度。项目事实与个人工作成果分别积累，供后续总结和面试使用。

学习过程中，用户可以随时记录想法、疑问、例子和实践发现，逐步形成自己的笔记。Learny 根据用户的整理要求补充、润色和排版，保留用户原始思路与材料出处。笔记成为之后回顾、补课、复习和成果整理的持续入口。

### 首版用户

首版面向一个正在学习实际项目的开发者，也支持希望补齐某个基础主题的学习者。用户可以修正目标和基础，允许中断后继续，不要求预先具备完整的学习计划。

| 使用目的 | 用户希望得到的结果 |
| --- | --- |
| 接手或理解项目 | 能追踪一条实际执行链路，解释关键设计，完成一个相关实践 |
| 补齐基础知识 | 知道先修关系，能用例子解释原理并完成练习 |
| 准备简历与面试 | 有依据的项目说明、真实的个人贡献和能够应对追问的表达 |

内部介绍和晋升答辩属于后续扩展，首版保留成果数据的扩展空间。

## 2 产品范围

### Demo 必须完成

- 创建学习空间，接受本地项目目录、本地文本材料或独立知识主题。
- 收集目标、已有基础和可投入时间，提供少量诊断题。
- 展示可调整的学习地图，节点包含先修关系、材料、实践与验收标准。
- 完成至少一个包含预测、阅读、实践、解释和评价的教学过程。
- 保存提交、辅助程度、评价、薄弱点和复习建议。
- 提供本地 Markdown 笔记系统，支持随手记录、编辑、查找、按用户要求整理和复习关联。
- 换聊天和重启后继续同一个学习空间。
- 从项目证据和用户补充信息生成总结与简历草稿。
- 开展一次项目面试，将发现的缺口反馈为学习任务。
- 打包为可安装插件，在目标 dsh 版本中验证。

首个演示空间控制在一条执行链路、3 个主要学习节点和少量外部原理资料。M1 使用人工准备的示例地图；M2 加入模型生成路线。内容范围与单次时长可调整，不要求 Demo 一开始自动覆盖整个仓库。

### 首版暂缓

团队协作、云端同步、多账户、全仓持续索引、大规模知识图谱、自动生成完整课程库、复杂多媒体课程、PPT 成果、晋升模板和无人值守定时复习暂缓。首版复习入口在用户打开学习空间时展示。

## 3 产品原则

1. 每次学习都有一个明确下一步。用户能够识别当前目标、需要投入的动作和完成条件。
2. 用户先尝试，再逐步获得帮助。提示按线索、解释、示例分层提供，并记录辅助程度。
3. 阅读完成只代表接触过。独立掌握必须关联任务标准和真实提交。
4. 项目事实带来源。原理解释说明与项目实现之间的联系，避免将一般规律直接当成本项目事实。
5. 学习过程跨聊天持续。聊天承载讨论，学习空间承载路线、进度、记录和成果。
6. 路线允许修正。修改目标或材料范围后保留旧版本及已有实践证据。
7. 成果尊重事实。个人贡献由用户提供，缺失的业务指标形成待补项。
8. 笔记由用户主导。记录自己的理解与疑问，整理遵循用户的思路；用户原文、模型补充和整理版本可追溯，允许撤销和继续修改。

## 4 核心用户流程

### 创建学习空间

用户选择“学习项目”或“学习一个主题”。项目空间选择本地目录及有限材料范围，主题空间填写主题并可附加材料。随后输入学习目的、基础、近期目标和可投入时间；能够跳过不确定的问题，以待补信息保存。

项目目录采用 Host 可访问的路径，由宿主目录选择能力提供。学习材料路径与当前 dsh 聊天工作目录需要明确对应；切换学习空间不自动改变聊天工作目录，路径不匹配时先引导用户选择合适的聊天或工作区。

提交后创建持久学习空间，再开始诊断和路线生成。生成失败时空间仍可打开，可修改材料或重试。

### 诊断与路线确认

诊断围绕目标提出少量具体问题，用户可以回答或选择“不知道”。结果用于调整起点，诊断本身不授予已掌握状态。

路线展示推荐顺序和原因。用户可跳过已经熟悉的节点、调整顺序或缩小范围；跳过与通过分别记录。先修节点未通过时允许用户选择挑战后续任务，界面显示所需基础，避免将推荐依赖变成阻止探索的锁定条件。

### 完成一个任务

| 阶段 | 用户动作 | Learny 支持 | 保存内容 |
| --- | --- | --- | --- |
| 预测 | 先说出对行为或执行顺序的判断 | 一个具体问题，暂不直接展示答案 | 原始判断 |
| 阅读与追踪 | 查看指定材料，定位调用关系 | 文件入口、阅读范围、外部原理资料 | 阅读记录与相关来源 |
| 实践 | 完成追踪、实验、小修改或练习 | 任务要求、提示、验证方式 | 文本、文件引用、实际运行结果 |
| 自己的解释 | 用自己的话解释做法、结果与原因 | 补问遗漏点 | 用户原文 |
| 评价 | 查看逐条验收结果，必要时提出异议 | 依据、薄弱点、辅助程度和下一步 | 提交及其评价版本 |

在每个阶段均可保存并离开。用户可直接求助，系统记录实际帮助情况。模型代写的解释或生成的示例不计为用户独立产出；用户可以在随后一次独立尝试中重新验证能力。

当前任务始终提供“记笔记”入口，可记录预测、阅读线索、实践发现或尚未解决的问题。用户可以把自己的解释保存到笔记，或引用某版笔记作为提交；提交保存当时的内容和辅助记录，后续润色不会改写已提交的原始解释。任务结束时可建议整理笔记，用户也可先继续学习，不以写完笔记作为通关条件。

### 记录与整理笔记

用户可以从当前任务、聊天中的一段内容或笔记视图开始记录。任务内新建笔记默认关联当前节点，空间内自由笔记可不关联节点。收藏聊天内容时保留引用和作者信息，用户可在其下补上自己的理解。

用户通过自然语言指定整理意图，例如“保留我的写法，补上这个例子”“把这些零散记录按执行顺序整理”“只修正排版”“帮我找出不准确和缺失的地方”。Learny 对选中段落或指定笔记执行相应操作，整理后仍能查看原始记录、变化和资料依据。

### 补课与复习

未达到验收标准时，提供针对具体缺口的小任务，说明对应哪个标准以及需要补充什么。再次提交形成新尝试，原尝试保留。

复习建议依据节点表现、提示使用和最近验证时间生成。首版在学习空间中显示待复习项，复习采用换一个例子、重新解释或再次实践的方式。计划日期到达或经过一段时间不自动将用户标为不会；一次复习失败保留历史通过证据，并提示能力需要重新验证。

复习可从关联笔记出发：先展示标题、用户留下的问题或自测题，尝试回忆，再展开正文核对，必要时完成新练习。用户可在笔记中追加“这次理解的变化”，保存复习记录并关联相应任务。

### 成果与面试

用户从学习记录和个人笔记中选择要整理的项目范围，生成项目总结。笔记中的项目事实沿用其来源，个人感想保留为用户理解。成果工作台继续收集个人负责范围、具体行为、协作对象、业务结果和指标口径，再生成简历草稿。

面试从成果内容和学习节点发起追问。每轮保存问题、用户回答和评价；发现薄弱点时提出补课任务，由用户选择加入路线。原成果和既有掌握记录不因一次模型追问被直接覆盖。

独立主题空间可生成知识总结和面试练习；只有关联真实项目经历及用户贡献后，才提供项目简历素材。

## 5 学习空间与界面

### 学习空间

每个空间独立保存材料范围、学习者信息、路线版本、当前任务、个人笔记、实践记录、能力证据和成果。一个空间可关联多个 dsh 聊天；Demo 中每个聊天同时绑定一个学习空间，切换绑定为显式操作。

重新打开关联聊天时显示空间名、当前节点和下一步。新聊天可以选择已有学习空间继续。绑定关系属于 Learny 数据，不能仅依赖右侧面板布局或聊天摘要。

### 五个界面视图

日常布局为左侧 dsh 对话、右侧 Learny 当前任务。地图、笔记、记录和成果在工作台内切换，并支持宿主提供的全屏呈现。任务内可以展开轻量笔记编辑区，记录后返回当前阶段；阅读资料时也能保持笔记入口可用。

| 视图 | 主要内容 | 核心操作 |
| --- | --- | --- |
| 当前任务 | 目标、阶段、材料、任务要求、提交、提示、验收标准 | 打开材料、请求提示、保存、提交、继续 |
| 学习地图 | 节点、先修关系、推荐顺序、状态、路线版本 | 选择节点、调整目标、跳过、挑战后续任务 |
| 我的笔记 | 空间笔记列表、编辑与预览、节点关联、来源、整理版本 | 新建、记录、查找、整理、恢复版本、导出 |
| 实践记录 | 尝试、用户原文、实践证据、辅助程度、评价依据 | 查看历史、重试、质疑评价、查看关联节点 |
| 成果工作台 | 总结、个人贡献、指标、待补信息、草稿版本、面试记录 | 补充事实、生成、编辑、导出、开始面试 |

工作台顶部显示空间名、切换入口和当前学习目标。大地图初版可用清晰的节点列表与依赖说明实现，优先保证路线和状态可理解。

### 反馈与异常状态

| 状态 | 用户看到的内容 | 可执行动作 |
| --- | --- | --- |
| 尚无学习空间 | 创建项目或主题入口，示例空间入口 | 创建或打开示例 |
| 正在分析或评价 | 当前阶段、运行状态、已保存的内容 | 取消并保留已有记录 |
| 资料缺失或读取失败 | 具体材料及受影响节点 | 修正路径、替换材料或缩小范围 |
| 网页不可用 | 原资料引用及获取失败状态 | 重试或提供本地材料 |
| 模型调用失败 | 已保存提交与失败阶段 | 重试该阶段 |
| 进程重启后存在运行中任务 | 显示任务已中断及最后保存阶段 | 从可恢复阶段继续 |
| 评价存在争议 | 原评价、引用依据及异议记录 | 补充证据并重新评价 |
| 笔记保存或整理失败 | 保存状态、用户当前内容、失败的整理操作 | 保留草稿、重试保存或整理 |
| 笔记被外部修改 | 当前文件与整理所依据的版本差异 | 重新读取、另存整理稿或手动合并 |

## 6 学习地图与材料

每个节点包含名称、能力目标、先修节点、关联项目位置、原理资料、实践任务、验收标准与下一步建议。验收标准在实践开始前可见；开始一次尝试时记录对应节点和路线版本，后续改路线不改变该次尝试的判定依据。

项目证据记录文件路径、版本或提交、内容哈希及相关片段位置。网页来源记录 URL、标题、获取时间及必要内容引用。材料发生变化时提示相关节点和成果需要核对；旧证据保留其原始版本。

节点依赖不得成环，引用必须指向已登记的来源。外部原理支持解释通用机制，源码和项目文档支持具体项目事实，用户陈述支持个人贡献。相互冲突的材料作为待核对信息显示。

首版支持源码、Markdown 和纯文本材料。其他复杂格式可先由用户提供文本导出，后续按实际需要增加解析能力。

## 7 个人笔记系统

### 首版能力

笔记是独立于聊天的个人学习内容，每个学习空间都有自己的笔记目录。首版使用普通 Markdown 文件，提供列表、标题和正文搜索、编辑、预览、节点关联与导出。允许直接记录零散内容，不要求先填写模板或完成一个学习任务。

| 操作 | 用户需求 | Learny 行为 |
| --- | --- | --- |
| 随手记录 | 保存想法、问题、代码片段或实验结果 | 自动保存草稿，显示保存状态，可关联当前节点和材料 |
| 补充 | 加一个例子、解释概念、补齐缺失步骤 | 在指定范围补充，标记补充来源及待核对内容 |
| 润色 | 更清楚地表达自己的意思 | 保留立场和疑问，改进语句，展示变化 |
| 排版 | 整理标题、列表、代码块和段落 | 只改变组织与呈现，不改变事实含义 |
| 重组 | 将零散记录按自己的思路整理 | 按用户要求调整结构，保留原始版本与来源 |
| 核对 | 查找不准确或证据不足的表述 | 给出纠正建议及依据，保留待确认的问题 |
| 复习 | 回顾自己的理解和未解决的问题 | 关联复习任务，先尝试回忆，再查看笔记和材料 |

可选的笔记提示包括“我的理解”“例子与实践”“还没想通的问题”“资料来源”“复习问题”。用户可以完全自由书写，Learny 不强制替换为固定结构。

### 整理规则

用户选择笔记或段落，并说明希望怎样整理。明确的局部修改可按要求直接应用；整理前保存原文快照，整理结果可编辑、对比和撤销。仅在修改意图含糊且会改变含义时澄清，不为每次自动保存或排版增加确认步骤。

用户的“不确定”“尚待验证”和个人判断在整理后继续保留。Learny 提供的事实补充记录引用，模型示例标明为补充内容；缺少来源时作为建议或待核对信息。收藏的 AI 回答保留其来源标识，不能伪装成用户独立写出的结论。

整理记录保存输入版本、用户指令、修改范围、模型补充、来源和结果版本。笔记更新不自动更新能力判断，也不改写历史实践提交；引用笔记作为验收证据时，使用当时的版本及实际辅助程度。

### Markdown 存储与文件访问

笔记正文以本地 `.md` 文件为权威内容，路径位于可配置的 Learny 数据目录下，按学习空间与稳定笔记 ID 组织。文件包含可读的正文与必要的 frontmatter，例如笔记 ID、空间 ID、标题和节点关联。标题修改不需要改变文件身份。

领域存储保存笔记索引、关联和整理运行记录，原文快照及修订版本保存在本地。正文不只存在于数据库或单条聊天里；用户可以打开文件，用外部编辑器修改，也可以导出到自己指定的目录。首版不引入独立的笔记云服务。

保存采用完整文件替换并提供失败恢复；索引与正文不同步时以文件重新建立索引。整理写入前检查输入版本，发现外部修改时保留原文件和整理稿，允许用户重新整理或合并。重启后能找到已保存笔记和版本，未完成整理可重试，不覆盖用户的新内容。

### 笔记与其他视图的关系

学习节点展示关联笔记，笔记也能返回对应材料和实践记录。同一个节点可关联多篇笔记，一篇笔记可关联多个节点。笔记中的疑问可以转为补课任务，模型建议的复习问题需由用户选择采用。

成果工作台可选用笔记的已保存版本，并带上来源及待核对信息。笔记提供个人学习积累，是否达到某项能力仍根据对应任务的验收判断。

首版暂缓双向链接图谱、复杂富文本协作和完整知识库插件生态。

## 8 验收与能力证据

### 节点进度与能力判断

节点进度用于导航，能力判断由尝试记录支持，两者分别保存。

| 表示 | 含义 | 所需记录 |
| --- | --- | --- |
| 未开始 | 尚无学习活动 | 无 |
| 学习中 | 当前正在执行某个阶段 | 活动与当前阶段 |
| 接触过 | 已阅读或看过示例 | 阅读记录 |
| 辅助完成 | 满足任务要求，但依赖提示、示例或共同完成 | 实践、解释、评价和辅助记录 |
| 独立通过 | 对本节点标准的独立尝试达到要求 | 实践、自己的解释、逐条评价和来源 |
| 需要补课 | 某些标准未达到要求 | 未满足标准及补课建议 |
| 待复习 | 到达建议复习时间或需要重新验证 | 最近证据与复习建议 |

“独立通过”只覆盖已验证的任务范围，不推定用户掌握整个技术领域。界面优先显示具体证据和能力描述，Demo 不使用一个总分代替解释。

### 评价规则

模型按照预先保存的标准，逐条给出“满足”“未满足”或“证据不足”，引用用户提交和材料中的依据，并指出薄弱点。证据不足时保留待验证状态，不作为通过。

程序校验标准覆盖、引用、任务版本、辅助记录与实践结果是否齐全，再决定允许保存的能力判断。程序校验能够防止无证据更新状态，但不等于自动证明解释语义完全正确；争议评价允许用户补充证据并生成新版本。

提示使用由工作台和 Agent 工具记录，并结合用户对独立完成情况的说明。系统无法观测的外部帮助标为未知；无法确认独立性的尝试不能自动认定独立通过。

### 实践证据

实践可以是执行链路说明、实际输出、文件变更引用或其他任务要求的产出。命令执行成功仅证明命令结果，仍需符合本节点目标。模型描述“已经运行成功”不能代替宿主返回的真实执行记录。

## 9 成果设计

| 数据类型 | 内容 | 信息来源 |
| --- | --- | --- |
| 项目事实 | 架构、流程、关键设计和技术取舍 | 源码与项目文档 |
| 学习能力 | 已能解释、追踪或完成的任务 | 通过验收的实践记录 |
| 个人贡献 | 负责范围、具体行动和个人角色 | 用户补充，必要时附材料 |
| 业务结果 | 收益、影响和结果指标 | 用户提供的口径与出处 |

项目总结按背景、核心流程、关键设计、理解依据和待核对信息组织。简历草稿按个人角色、行动、技术难点、结果组织；缺少个人经历时先形成项目理解素材。

指标需要保存值和单位、测量对象、统计口径、时间范围、基准及出处。信息不完整时形成待补问题，不编造提升百分比，也不把整个团队成果默认归给用户。

成果草稿保存版本、所用证据和待补信息，允许用户编辑。导出首版为 Markdown 或纯文本；生成新版本不覆盖历史版本。用户修改正文后保留来源关联，已修改的事实主张需要重新核对。

## 10 数据与恢复要求

| 对象 | 主要信息 |
| --- | --- |
| Workspace 与 LearnerProfile | 材料范围、目的、基础、时间、聊天关联 |
| Source 与 Evidence | 文件或网页位置、内容版本、获取时间、事实依据 |
| LearningPlan 与 LearningNode | 路线版本、目标、依赖、任务、验收标准 |
| Note 与 NoteRevision | Markdown 路径、笔记关联、内容版本、原文快照、整理指令和修改来源 |
| Review | 关联节点与笔记版本、自测问题、回忆结果和复习记录 |
| Activity 与 Attempt | 阶段、原始回答、实践提交、辅助记录 |
| Evaluation | 标准逐条判定、引用依据、薄弱点、评价版本 |
| Mastery | 由尝试推导的能力判断、证据和复习建议 |
| Contribution 与 Metric | 用户负责范围、结果、测量口径和出处 |
| Artifact | 成果版本、正文、引用证据、待补信息 |
| Run | 执行阶段、状态、结果、错误和重试信息 |

学习数据是业务记录，聊天日志保存交互和模型可见上下文，笔记文件保存可持续编辑的个人知识内容，导出文件保存用户产出。只清空或切换一个聊天，不应丢失学习空间及笔记。

保存成功必须代表本地持久化已完成。重启后读取权威业务记录恢复进度；界面断开重连后重新读取快照。未完成的生成、评价或导出任务标为中断；已完成的结果保留。实践命令不在重启后自动重放。

Demo 将一次尝试及其评价保存在单条权威记录内，能力视图由记录重新计算，以适应宿主当前缺少跨表事务的领域存储。数据结构变更时必须有明确的导出、备份与迁移策略，禁止为了重试直接清除用户记录。

## 11 运行与产品边界

Learny 作为 dsh 插件运行，复用宿主的模型、Agent、对话、文件与网页工具、界面扩展和本地存储。客户端负责交互；本地 Host 负责领域服务、材料访问与记录；独立 TypeScript 核心负责教学状态和业务规则。UI API 与 Agent 工具调用同一领域服务。

模型提出学习路线、评价和成果草稿，领域服务校验后保存。模型没有任意写入掌握状态的入口。影响模型判断的学习状态通过宿主支持的消息或工具结果进入会话日志，支持后续追踪。

应用数据保存在本机，无需部署 Learny 应用服务器。模型请求和网页搜索可能将相关材料发往外部服务，按宿主配置使用；产品界面说明这与本地存储的区别。材料范围由用户选择，实践执行遵循宿主的权限与沙箱机制。

宿主版本和具体集成方式以 [dsh 开发基线](runtime-baseline.md) 为准。Demo 不额外叠加 Agent 框架，长期教学状态由插件管理。

## 12 Demo 验收

| 编号 | 验收场景 | 通过条件 |
| --- | --- | --- |
| A01 | 创建学习空间 | 项目或主题范围、学习目标已持久保存 |
| A02 | 展示学习地图 | 节点具有目标、材料、任务、标准和合法依赖 |
| A03 | 完成学习任务 | 预测、实践和自己的解释均有原始记录 |
| A04 | 区分辅助与独立 | 阅读、提示或代写不能被直接保存为独立通过 |
| A05 | 失败后补课 | 未满足标准生成对应补课任务，旧尝试仍可查看 |
| A06 | 换聊天继续 | 新聊天关联同一空间，当前任务和历史一致 |
| A07 | 重启与中断 | 已保存数据恢复，未完成运行标为中断且可重试 |
| A08 | 成果有据 | 项目事实可追溯，贡献由用户提供，缺失指标为待补项 |
| A09 | 面试反馈 | 问答和评价保存，至少一个缺口可以加入路线 |
| A10 | 安装交付 | 独立插件包在基线版本中安装并完成上述演示 |
| A11 | 笔记记录与查找 | 在任务中记录并保存 Markdown 笔记，按标题或正文查找，换聊天和重启后可继续编辑 |
| A12 | 按意图整理 | 补充、润色、排版遵循用户指令，原文可恢复，AI 补充与来源可追溯 |
| A13 | 笔记复习与成果 | 从关联笔记完成一次回忆练习，保存复习记录，并引用指定笔记版本整理成果 |
| A14 | 外部编辑与恢复 | 外部修改后重新读取，不被过期整理结果覆盖；保存或整理失败时原文仍可恢复 |

体验评估使用同模型、同材料、相近学习时长，与普通聊天比较独立解释、实践完成、延迟回忆和成果追问表现。Demo 先记录任务级结果与用户反馈，不预设提升百分比。

## 13 后续扩展

Demo 跑通后，依据真实使用反馈选择扩展：更多学习主题和材料格式、复习提醒、内部介绍和晋升模板、可分享成果、更细的能力画像。优先验证学习效果和持续使用，再扩大课程与自动化范围。
