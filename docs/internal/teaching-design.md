# Learny 教学章节设计

状态：2026-10-20 第一版。研究形成的产品规范，仍需真实学习者试读；提示词遵循度不等于教学效果。

## 问题与交付物

节点导读用于选课；正式章节用于自学；追问用于解决局部困惑。三者不能共用一份短摘要要求。

旧原生教学提示固定为“解决什么问题 / 关键机制 / 下一步”，只有加粗标题；旧独立教程接口限制 350～700 字。这会鼓励压缩、名词罗列和省略推导。另有证据问题：路线要点本身由模型生成，源文档也可能含概括失真，不能当作已验证结论复述。

课程的主交付物是原生 dsh 对话中的完整中文章节。Learny 继续负责空间、路线、资料和笔记。备课、读取文件、搜索、讲授和局部追问继续使用宿主 Agent，不新增一个并行聊天系统。

## 一章的生成过程

1. 备课：读取学习者目标、当前章节、真实先备章节、下一节边界，以及已有 criteria 中的学习结果；选择中心问题和贯穿案例。
2. 核实：原生 Agent 阅读必要原文件；缺少前提原理时查官方资料。来源摘录、路线要点、历史回答都不能替代证据核对。旧独立 lesson API 无工具，明确限于传入材料。
3. 成文：章标题、学习结果与阅读路线 → 按依赖展开的具体小节 → 贯穿案例的完整示范 → 关系回收与下一章连接。小节名、数量和内容按课题决定。
4. 复核：逐项目标核对覆盖范围、前提、推理、示例与证据；缺项先修订。当前由宿主 Agent 执行指令，尚无独立审稿器或自动发布门禁。
5. 反馈：学习者追问卡点时，补讲对应概念或例子；完整章节模式不强加给普通短追问。

不限制为统一字数；篇幅服从推导所需。达到单次输出预算时，明确哪些小节尚未交付，不能假装完整。图块放在正文需要的位置，不限制全章数量，图前后有讲解。讲解必须与假设场景、预期输出和实际验证区分。

## CubeSandbox 第一章的候选提纲

以下是编排示例，具体事实必须在生成时核对当前仓库：

中心问题：从“我调用创建沙箱”到“我访问沙箱内服务”，系统为什么需要不同层次的组件？

学习结果：能区分创建与访问路径；能解释网关、集群调度与节点执行的边界；能区分逻辑组件、进程和内核能力；能把假设故障定位到需要继续核查的层。

1. 从已有后端经验出发：普通 HTTP 服务与隔离执行环境分别提供什么。
2. 用“创建一个运行 Web 服务的沙箱”串起管理请求与业务访问两个阶段。
3. 为什么接单、选节点、节点执行需要分工；讲清控制面和数据面的含义，再落到项目组件。
4. 在节点内怎样把运行时请求交给虚拟机执行；首次使用时解释 containerd Shim、VMM、KVM，区分逻辑图与进程图。
5. 把同一个请求完整走一遍：各层接收什么、做什么、向下交付什么、返回什么。
6. 对比“创建未成功”与“创建成功但访问失败”两个假设情形，示范怎样运用边界推理；不把症状直接等同唯一原因。
7. 收拢关系，可选自测，连接下一章 SDK 请求参数。

注意待核实的旧错误：不能把 Redis 也描述成无状态；不能把逻辑组件都视为独立进程；不能沿用旧回答对 rust-vmm 的错误定义；当前 CubeAPI 创建调用的 HTTP 实现与概览图 gRPC 标记需交叉核对；文档里的延迟与内存指标不能声称已由读代码验证。

## 人工评审标准

| 维度 | 可检查的证据 | 不接受 |
| --- | --- | --- |
| 章节逻辑 | 小节顺序遵循概念依赖，前后有连接 | 换上 H3 的三个摘要段 |
| 概念深度 | 首次定义、原因、机制、项目对应与边界 | 一行职责 + 一堆术语 |
| 示范完整 | 同一案例有起点、中间观察、结果及解释 | 只给箭头或只让用户自己做 |
| 证据准确 | 具体断言可回查文件或官方资料 | 引用存在但内容不支持结论 |
| 学习者匹配 | 补足未知前提，环境与实践安排可行 | macOS 上要求直接部署 KVM |
| 学习连续性 | 与先备、下一章形成联系，可局部追问 | 重复全章或把没讲过的内容当已知 |

自动测试只能验证上下文传递、数据持久化、格式恢复等软件行为。字数、标题数量、测验完成率都不能单独证明学会。第一轮试读仍需检查读者能否用自己的话解释边界，并将其应用于新场景。

## 首次实测发现与修订

第一轮真实重讲增加了标题，却只重新读取 README 和 overview，未读取关键实现，仍复述了有问题的协议标记与“控制面全部无状态”的概括。它还把“先不深入代码”误解为教师备课也无需核对实现。这一稿不作为合格样例。

据此加强了共同教学指令：概览章节也须核对具体协议、调用和进程边界；自动导读和旧 criteria 可根据学习目标修正；核心前提不能以“只要记住”省略；贯穿示范需要具体输入、中间观察与结果，职责清单不算示范。此过程仍属人工评审驱动的迭代，不宣称提示词可保证输出质量。


第二轮自动任务虽读取了 Cargo/go.mod 和 proto，却仍把“有依赖/有接口定义”误当为具体调用已核实，未发现 API→Master 的 HTTP 实现。教学仍较接近组件职责清单，因此也未通过内容评审。

补充具体的人工编审反馈、贯穿场景、章节提纲与核查文件定位后，原生导师生成了七个小节：概念 → 创建与访问两个阶段 → 分层原因 → 两段源码交接示范 → 业务访问 → 假设故障推理 → 回收与自测。确实更正了 HTTP/gRPC、Redis 状态与 Shim/VMM 库调用关系，并在对话正文渲染了图和自测。但仍有遗漏：rust-vmm 术语沿用了模糊说法，安全隔离与架构分类有绝对化表述，“创建成功则不再查控制面”等排障说法排除得过早，章节衔接还把创建入口误称为第二阶段。该稿只能作结构试读，不能标为发布级教程。未部署 CubeSandbox、未进行 KVM 运行验证。

## 后续应实现的质量控制

以下是设计结论，尚未实现为自动门禁：

- **章节计划**：先记录学习结果、已知基础、待补概念、贯穿场景、分节目的/依赖/示范步骤、所需证据及缺口，再据此写正文。计划由宿主 Agent 使用，学习者仍在原生对话阅读。
- **断言与证据对齐**：协议核对发送与接收实现，进程边界核对启动与库依赖；只找到接口定义或依赖，不足以证实调用。通用原理用官方资料补足，缺证据时明确范围。
- **内容评审记录**：分别检查目标覆盖、概念依赖、示范完整、证据支持和表述边界。发现问题定位到小节并修订；“有标题、有引用、有测验”均不能直接判为合格。
- **章节版本**：保留草稿、修订依据和当前推荐版本，避免多轮对话中旧错误与新修订难以分辨。目前保留对话历史和重讲任务记录，尚无正式章节版本状态。

这次试验验证了软件上下文与原生教学联动，但没有验证自动课程的可靠教学效果。64 项自动测试覆盖软件行为；最终文字是否正确、足够清楚仍需要试读与内容审查。


## 来源的阅读体验

教学正文不展示 `[project-1]`、`[web-2]` 等内部标识。文件名、函数名和经读取确认的行号仍可以作为源码讲解的一部分；文档冲突、未验证结论等限定必须保留在对应段落。

完整章节与教学追问共用来源呈现规则：回答末尾输出 `learny` 的 `sources` 围栏，包含实际使用的资料标题、原地址、支持内容以及可选的已有 `sourceId`。客户端将其显示为默认收起的「本章依据」。来源块只展示模型提供的依据，并不代表程序已自动验证断言。源资料和块中的追踪字段继续保留。

网页来源通过 HTTP(S) 链接打开；本地文件以可识别的路径文字展示，浏览器不会伪装成可以打开 `file:` 的网页链接。异常或格式错误的块保留代码显示。历史会话日志不修改，重新讲解使用新规则；旧回答中的编号不会被全局正则删除，以免误改代码或其他会话内容。
